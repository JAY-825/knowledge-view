# .gitignore 学习文档

.gitignore 用于告诉 Git 忽略哪些文件（不纳入版本控制）。它仅影响“未被跟踪”的文件；对已被跟踪的文件无效（需手动停止跟踪）。

# 作用场景

  • 屏蔽构建产物：dist/、build/、coverage/
  • 屏蔽依赖目录与缓存：node_modules/、.pnpm-store/、.cache/
  • 屏蔽临时文件与编辑器文件：*.log、*.tmp、*.swp、.DS_Store、Thumbs.db
  • 屏蔽本地配置与密钥：.env、.env.*、*.key、*.pem
  • 屏蔽生成的类型或 API 文件：*.d.ts（仅当生成且不希望跟踪时）

# 规则语法

  • # 开头为注释；如需匹配以 # 开头的文件名，使用转义 \#file
  • 空行不匹配任何内容
  • ! 取反：取消前面的忽略规则（后者优先）
  • / 锚定路径：
    • 以 / 开头表示相对于 .gitignore 所在目录（通常是仓库根）
    • 以 / 结尾表示“仅目录”
  • 通配：
    • * 匹配任意字符串（不含路径分隔符 /）
    • ? 匹配任意单个字符（不含 /）
    • [abc] 字符集匹配其中之一；支持范围 [0-9]
    • ** 可跨目录匹配（任意层级）

# 匹配规则详解

  • 目录匹配：logs/ 忽略 logs 目录及其下所有内容
  • 文件扩展名：*.log 忽略所有以 .log 结尾的文件
  • 局部规则：在子目录中放置 .gitignore 仅影响该目录与其子目录
  • 取反示例：
    • dist/ 忽略所有构建产物
    • !dist/keep/** 保留 dist/keep 下的文件（即使在忽略范围内）
  • 根目录限定：/env/ 仅忽略仓库根下的 env 目录，不影响 apps/app/env
  • 任意层级：**/.env 忽略任意层级目录下的 .env

# 优先级与覆盖

  • 多个 .gitignore 可同时生效（根目录与子目录）
  • 规则按文件从上到下匹配；后出现的规则优先生效（取反通常写在后面）
  • 仅影响“未跟踪文件”：若文件已入库，需使用 git rm --cached <path> 停止跟踪
  • 其他忽略来源：
    • 仓库级：.git/info/exclude（仅本地）
    • 全局：core.excludesFile（如 ~/.gitignore_global）

# 实践建议

  • 将“不可复现的产物/环境专属文件”置于忽略列表；保留“必要的构建配置与源代码”
  • 对需要保留的产物（如占位文件）使用取反并放置在更靠后位置
  • 对密钥与敏感信息严格忽略；若误提交，使用历史清理工具（如 BFG/git filter-repo）
  • 使用团队全局忽略文件（如 ~/.gitignore_global）统一系统与编辑器垃圾文件
  • 添加或修改 .gitignore 后，若需要停止跟踪已提交文件，执行：
    • git rm --cached -r <path> 并提交变更；后续该文件将被忽略
