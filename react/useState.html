# useState（React）

useState 用于在函数组件中声明状态（state）。当你调用它返回的更新函数设置新状态后，React 会触发一次重新渲染，并在下一次渲染中拿到最新的状态值。

const [state, setState] = useState(initialState);
1
  • initialState：初始状态。可以是任意值，也可以是一个“初始化函数”（惰性初始化）。
  • 返回值：数组 [state, setState]
    • state：当前状态
    • setState(next)：更新状态并触发渲染

# 一、基础用法

# 1. 声明与读取状态

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      count: {count}
    </button>
  );
}

# 二、初始化技巧

# 1. 惰性初始化（只在首次渲染执行一次）

当初始值计算比较昂贵时，不要在渲染时直接执行计算，而是把“生成初始值”的逻辑放在函数里传给 useState。React 只会在首次渲染时调用该函数并缓存结果。

import { useState } from 'react';

function buildLargeArray() {
  return new Array(100000).fill(0);
}

export function Example() {
  const [list] = useState(buildLargeArray);
  return <div>length: {list.length}</div>;
}

# 三、更新规则与推荐写法

# 1. 函数式更新：基于“上一次状态”计算下一次

当新状态依赖旧状态时，推荐使用函数式更新，避免“读取到旧值”的问题。

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  const addTwice = () => {
    setCount((c) => c + 1);
    setCount((c) => c + 1);
  };

  return <button onClick={addTwice}>count: {count}</button>;
}

# 2. 更新是异步“排队”的：不要依赖 setState 之后立刻读到新值

调用 setState 并不会立刻修改当前渲染中的 state 变量，它会为下一次渲染安排更新。因此，在同一次事件处理函数里，state 仍然是旧值。需要基于旧值计算时使用函数式更新；需要在值变化后做副作用时使用 useEffect。

# 3. React 18 自动批处理（Batching）

在 React 18 中，更多场景会自动合并多次状态更新，从而减少渲染次数。你不需要为了“立即生效”而拆分更新；要确保更新逻辑是纯的，并用函数式更新表达“依赖旧值”的情况。

# 4. 状态更新是“替换”而不是“合并”

类组件 setState 会合并对象；useState 的 setState 不会合并，它会用新值替换旧值。因此更新对象/数组时要创建新引用（不可变更新）。

# 4.1 更新对象

import { useState } from 'react';

export function Profile() {
  const [profile, setProfile] = useState({ name: 'Ada', age: 20 });

  const onBirthday = () => {
    setProfile((p) => ({ ...p, age: p.age + 1 }));
  };

  return (
    <div>
      <div>{profile.name}</div>
      <div>{profile.age}</div>
      <button onClick={onBirthday}>birthday</button>
    </div>
  );
}

# 4.2 更新数组

import { useState } from 'react';

export function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: 'learn', done: false },
    { id: 2, text: 'build', done: true },
  ]);

  const toggle = (id) => {
    setTodos((prev) =>
      prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
    );
  };

  const remove = (id) => {
    setTodos((prev) => prev.filter((t) => t.id !== id));
  };

  return (
    <ul>
      {todos.map((t) => (
        <li key={t.id}>
          <button onClick={() => toggle(t.id)}>
            {t.done ? 'done' : 'todo'}
          </button>
          <span>{t.text}</span>
          <button onClick={() => remove(t.id)}>remove</button>
        </li>
      ))}
    </ul>
  );
}

# 5. 相同值可能不会触发重渲染

React 使用 Object.is 判断新旧 state 是否相同；如果相同，可能会跳过重渲染。对对象/数组进行“原地修改”后再 setState 传回同一个引用，通常不会触发更新，也会让 UI 与状态不一致。正确做法是创建新对象/新数组。

# 四、常见坑与建议

# 1. 闭包导致的“陈旧状态”

事件处理、定时器、订阅回调中读取到的 state 可能不是你以为的“最新值”，尤其当你把回调保存下来并在未来执行时。常见解决方式：

  • 需要基于旧值更新时，用函数式更新：setState((prev) => next)
  • 需要在某个值变化后执行逻辑时，用 useEffect 监听它
  • 需要一个可变容器保存最新值时，用 useRef

# 2. 不要在条件/循环/嵌套函数里调用 useState

Hooks 必须在组件顶层调用，保证每次渲染的调用顺序一致。

# 3. 严格模式（Strict Mode）下开发环境的“重复调用”

在开发环境开启严格模式时，React 可能会对某些函数进行额外调用以帮助发现副作用问题，例如惰性初始化函数、函数式更新器等。它们应当是纯函数：不读写外部可变状态、不执行网络请求、不做订阅等副作用。

# 4. 避免在渲染期间直接 setState

渲染阶段调用 setState 会导致重复渲染甚至死循环。需要在某个条件成立时更新状态，应把逻辑放到事件处理函数或 useEffect 中。

# 五、何时不该用 useState

  • 可推导状态：如果某个值可以由 props 或已有状态计算得出，优先在渲染中直接计算；必要时用 useMemo 做性能优化，而不是再存一份 state。
  • 复杂状态机/多分支更新：当更新逻辑越来越像“根据 action 分发”，考虑用 useReducer 替代 useState。
  • 跨组件共享：如果多个组件需要共享同一份状态，考虑上移状态、使用 Context，或引入合适的状态管理方案。
