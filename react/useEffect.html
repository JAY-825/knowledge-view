# useEffect（React）

useEffect 用于在函数组件渲染到屏幕后执行副作用（side effects），并在依赖变化或组件卸载时做清理。常见副作用包括：数据请求、订阅、事件监听、定时器、与非 React 系统的集成（例如操作 DOM/调用第三方 SDK）。

useEffect(setup, dependencies?)
1
  • setup：副作用函数。可以返回一个清理函数 cleanup。
  • dependencies：依赖数组。React 用它判断何时需要重新执行副作用。

# 一、它解决什么问题

React 渲染的职责是“根据数据计算 UI”。副作用会触碰 React 体系外部的世界（网络、浏览器 API、订阅系统、计时器、日志等），不适合放在渲染阶段执行。useEffect 让你把这些操作放到“渲染提交之后”执行，并提供统一的清理机制，避免泄漏与重复订阅。

# 二、执行时机与依赖数组

# 1. 没有依赖数组：每次渲染后都执行

import { useEffect, useState } from 'react';

export function Example() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `count: ${count}`;
  });

  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}

# 3. 指定依赖 [a, b]：依赖变化后执行，并在下一次执行前先清理

当依赖变化时，React 会按顺序做三件事：

  1. 先调用上一次 effect 返回的 cleanup
  2. 再调用本次渲染对应的 setup
  3. 等到卸载时，最后再调用一次 cleanup
import { useEffect, useState } from 'react';

export function Example() {
  const [roomId, setRoomId] = useState('general');

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);

  return (
    <select value={roomId} onChange={(e) => setRoomId(e.target.value)}>
      <option value="general">general</option>
      <option value="random">random</option>
    </select>
  );
}

function createConnection(roomId) {
  return {
    connect() {},
    disconnect() {},
  };
}

# 三、常见使用场景（带示例）

# 1. 数据请求：支持取消与竞态处理

请求是典型副作用。需要处理两个问题：

  • 组件卸载或参数变化时取消请求
  • 避免旧请求晚于新请求返回导致“数据倒灌”
import { useEffect, useState } from 'react';

export function UserProfile({ userId }) {
  const [state, setState] = useState({ loading: true, error: null, user: null });

  useEffect(() => {
    const controller = new AbortController();
    setState({ loading: true, error: null, user: null });

    fetch(`/api/users/${userId}`, { signal: controller.signal })
      .then((r) => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json();
      })
      .then((user) => setState({ loading: false, error: null, user }))
      .catch((err) => {
        if (err.name === 'AbortError') return;
        setState({ loading: false, error: err, user: null });
      });

    return () => controller.abort();
  }, [userId]);

  if (state.loading) return <div>Loading...</div>;
  if (state.error) return <div>Error: {String(state.error.message || state.error)}</div>;
  return <div>{state.user?.name}</div>;
}

# 2. 订阅外部系统：确保成对订阅/退订

import { useEffect, useState } from 'react';

export function Clock() {
  const [now, setNow] = useState(() => new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);
  }, []);

  return <div>{now.toLocaleTimeString()}</div>;
}

# 3. 事件监听：注意 handler 的稳定性与依赖

如果 handler 使用了组件内的状态/props，那么它依赖哪些值就应该被纳入依赖数组。更通用的做法是把 handler 定义在 effect 内部，依赖更清晰。

import { useEffect, useState } from 'react';

export function KeyLogger() {
  const [lastKey, setLastKey] = useState('');

  useEffect(() => {
    const onKeyDown = (e) => setLastKey(e.key);
    window.addEventListener('keydown', onKeyDown);
    return () => window.removeEventListener('keydown', onKeyDown);
  }, []);

  return <div>last key: {lastKey}</div>;
}

# 4. 同步浏览器 API：例如 document.title、本地存储

import { useEffect, useState } from 'react';

export function Draft() {
  const [text, setText] = useState(() => localStorage.getItem('draft') ?? '');

  useEffect(() => {
    localStorage.setItem('draft', text);
  }, [text]);

  useEffect(() => {
    document.title = text ? `Draft (${text.length})` : 'Draft';
  }, [text]);

  return <textarea value={text} onChange={(e) => setText(e.target.value)} />;
}

# 5. 与第三方 UI/DOM 集成：在 cleanup 中恢复或销毁

当你需要创建一个外部实例并挂到 DOM 上时，把“创建/销毁”放在 effect 里，并确保引用的 DOM 节点稳定。

import { useEffect, useRef } from 'react';

export function ThirdPartyWidget({ options }) {
  const containerRef = useRef(null);

  useEffect(() => {
    if (!containerRef.current) return;
    const widget = createWidget(containerRef.current, options);
    return () => widget.destroy();
  }, [options]);

  return <div ref={containerRef} />;
}

function createWidget(el, options) {
  return {
    destroy() {},
  };
}

# 四、注意事项与常见坑

# 1. 不要把副作用写在渲染期间

渲染应当是纯的：同样的 props/state 返回同样的 UI。像发请求、改全局变量、订阅等行为，放到 useEffect。

# 2. 依赖数组必须准确表达“使用了哪些值”

setup 中读取的 props、state、以及在组件内声明的函数/对象，通常都属于依赖。依赖不完整会导致读取到旧值、漏更新或难以复现的 bug。

# 3. 避免在依赖里放“每次渲染都会变”的对象/函数

useEffect(() => {
  doSomething(options);
}, [options]);
1
2
3

如果 options 是在渲染中临时创建的对象，那么每次渲染引用都不同，effect 会频繁执行。常见做法：

  • 用 useMemo 缓存对象/数组
  • 把计算移进 effect 内，依赖只保留原始值
  • 将相关状态拆分为基础类型（string/number/boolean）作为依赖

# 4. 小心“无限循环”：effect 更新了它的依赖

useEffect(() => {
  setCount(count + 1);
}, [count]);
1
2
3

这会导致每次执行 effect 都触发下一次渲染，从而循环。通常说明你把“应该由渲染推导的值”塞进了 state，或把更新时机放错了位置。优先考虑：

  • 值能否由现有 state/props 直接计算得到
  • 更新是否应该由事件触发（点击、输入）而不是 effect
  • 是否应使用 useReducer 管理复杂更新逻辑

# 5. cleanup 里要对称清理：订阅/监听/定时器/外部实例

只要 effect 做了“注册”类动作，就必须返回 cleanup。否则会产生内存泄漏、重复监听、重复订阅等问题。

# 6. React 严格模式下开发环境的“额外运行”

在开发环境开启严格模式时，React 可能会额外执行一次 setup/cleanup 组合，以帮助你发现没有正确清理的副作用。你的 effect 应当满足：

  • setup 可以重复执行，不依赖“只执行一次”的隐含前提
  • cleanup 能完全撤销 setup 的影响

# 7. 不要用 useEffect 做“数据派生”

如果某个值可以从 props/state 直接计算出来，优先在渲染中计算，而不是：

useEffect(() => setFullName(first + last), [first, last]);
1

这种写法增加了额外状态与渲染次数，也更容易造成同步问题。

# 五、useEffect 与相关能力的区别

# 1. useEffect vs 事件处理函数

  • 用户交互触发的逻辑（点击提交、输入校验、按钮跳转）优先放在事件处理函数里
  • 需要与外部系统同步（订阅、计时器、请求、document.title）优先放在 useEffect

# 2. useEffect vs useLayoutEffect

  • useEffect：在浏览器绘制之后执行，更适合绝大多数副作用
  • useLayoutEffect：在浏览器绘制之前执行，适合需要读取布局并同步写入样式避免闪烁的场景（例如测量元素尺寸并立即调整）

除非你明确需要“阻塞绘制”，否则默认使用 useEffect。

# 六、快速检查清单

  • 依赖数组是否准确表达了 effect 使用的值
  • 是否在 cleanup 中撤销了订阅/监听/定时器/实例
  • 是否把可推导的值错误地放进了 state，再用 effect 同步
  • 是否意外创建了每次渲染变化的依赖（对象/数组/函数）
  • 是否正确处理了请求取消与竞态
