# VSCode 开发常用插件（推荐清单）

本文整理常用 VSCode 插件的用途、适合场景与使用技巧，便于快速搭建一套稳定的开发环境。插件并非装得越多越好，建议按项目栈选择。

# 一、基础必装

# 1. 中文语言包

插件名

Chinese (Simplified) (简体中文) Language Pack for Visual Studio Code

用途

将 VSCode UI 菜单与提示切换为中文，方便新手理解。

使用技巧

  • 安装后通常需要重启 VSCode 才会生效
  • 如果团队协作（截图/录屏）需要统一语言，建议统一使用英文 UI，避免菜单项名称不一致

# 2. 文件图标

插件名

vscode-icons

用途

为文件与目录显示更直观的图标，提升识别效率。

使用技巧

  • 插件安装后如果图标未生效，可在命令面板中搜索 “Icons” 相关选项切换主题

# 3. 主题

插件名

One Dark Pro

用途

提供常用暗色主题，降低长时间编码的视觉疲劳。

使用技巧

  • 在设置里调整 Editor: Font Ligatures、Editor: Font Size 让界面更舒适
  • 主题不影响代码格式化，但会影响语义高亮的可读性，建议选择对比度适中的配色

# 二、前端开发效率

# 1. Live Server（本地静态服务）

插件名

Live Server

用途

启动本地静态服务器并自动刷新页面，适合纯 HTML/CSS/JS 或简单 Demo 调试。

使用技巧

  • 右键 HTML 文件选择 Open with Live Server
  • 避免把它当作框架开发服务器替代品（React/Vue/Vite/Next/Nuxt 等更适合用项目自带 dev server）

# 2. Open in Browser（在浏览器打开文件）

插件名

Open in Browser

用途

快速用默认浏览器打开当前文件（或其预览链接）。

使用技巧

  • 适合临时查看静态页面或构建产物
  • 如果你使用 Live Server，更推荐直接用 Live Server 的 URL 进行调试

# 3. Auto Rename Tag（自动同步标签名）

插件名

Auto Rename Tag

用途

编辑 HTML/XML/Vue 模板时，自动同步开始/结束标签名称，减少低级错误。

使用技巧

  • 对 JSX/TSX、Vue SFC、HTML 文件都非常实用
  • 如果发现误触发，通常是语法模式识别问题，确认文件语言模式是否正确

# 4. 代码格式化（建议优先使用 Prettier + ESLint）

你文档里提到的 JS-CSS-HTML Formatter 能做简单格式化，但现代前端项目更建议使用：

  • Prettier - Code formatter
  • ESLint

使用技巧

  • 开启保存自动格式化：设置 Editor: Format On Save
  • 只让一个工具负责“格式化”，避免 Prettier 与 ESLint/其他 formatter 打架

# 三、Vue 开发

# 1. Vue 2：Vetur

插件名

Vetur

用途

为 Vue 2 的 .vue 单文件组件提供语法高亮、智能提示、格式化等能力。

使用技巧

  • Vue 2 项目中使用 Vetur 一般更省心
  • 如果项目升级到 Vue 3，优先切到 Volar，避免两套语言服务冲突

# 2. Vue 3：Volar

插件名

Vue Language Features (Volar)

用途

Vue 3 官方推荐语言服务，TS 支持更好，类型提示更准确。

使用技巧

  • Vue 3 项目通常只需要 Volar
  • 若你同时装了 Vetur，建议在 Vue 3 项目中禁用 Vetur（只在工作区禁用即可）

# 3. Vue 3 + TypeScript：TypeScript Vue Plugin

插件名

TypeScript Vue Plugin (Volar)

用途

增强 TS 在 .vue 文件中的类型分析体验（尤其是模板推断）。

使用技巧

  • 当你希望模板中 props/emit/ref 的类型提示更完整时启用
  • 遇到类型提示异常时，先尝试重载窗口（Reload Window）或重启 TS Server

# 四、React 开发

# 1. 代码片段（Snippets）

插件名

  • Simple React Snippets
  • JS JSX Snippets

用途

提供常用 React/JSX 片段，提升组件模板编写速度。

使用技巧

  • 片段只是“起步加速”，更建议在团队内统一组件模板、文件命名与 hooks 规范
  • 如果片段触发冲突（同名缩写），保留一个插件即可

# 五、Git 与提交规范

# 1. GitLens（源代码与提交信息增强）

插件名

GitLens

用途

查看每行代码最后提交者、提交信息、分支对比、历史追踪等，是最常用的 Git 增强插件之一。

使用技巧

  • 对性能敏感时可以在设置里关闭部分 blame 实时显示
  • 用它追查“谁改坏了”很高效，但也要注意团队协作语气与沟通方式

# 2. Git History（历史记录查看）

插件名

Git History

用途

以图形化方式查看文件/分支的历史提交记录。

使用技巧

  • 适合做某个文件的变更回溯与 diff 对比

# 3. gitignore（生成/维护 .gitignore）

插件名

gitignore

用途

快捷生成常见语言/框架的 .gitignore 模板，减少手写错误。

使用技巧

  • 模板生成后仍建议按项目需要做二次调整（例如构建产物、日志、临时文件等）

# 4. git-commit-lint-vscode（提交信息校验）

插件名

git-commit-lint-vscode

用途

在 VSCode 内编写提交信息时进行提示与校验，辅助遵循提交规范（如 Conventional Commits）。

使用技巧

  • 插件能提示，但真正的“强制校验”建议放在项目的 hooks/CI 中完成

# 六、通用使用技巧（不依赖插件）

# 1. 常用快捷键与命令

  • 命令面板：Ctrl + Shift + P
  • 快速打开文件：Ctrl + P
  • 多光标：Alt + Click / Ctrl + Alt + ↑↓
  • 重启语言服务：TypeScript: Restart TS Server
  • 重新加载窗口：Developer: Reload Window

# 2. 建议的基础设置方向

  • 开启保存自动格式化（配合 Prettier/ESLint 其一）
  • 开启自动保存（看个人习惯）：files.autoSave
  • 统一换行符与缩进（团队协作避免 diff 噪音）
