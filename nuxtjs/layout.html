# Nuxt.js 布局系统

Nuxt.js 的布局系统用于抽离页面的公共结构，例如头部导航、侧边栏、页脚、后台外壳、用户中心容器等。通过布局，可以让多个页面复用同一套页面骨架，只保留页面本身的业务内容，提高项目结构清晰度和维护效率。

在 Nuxt 3 中，布局文件通常放在 layouts/ 目录下，页面通过 definePageMeta 或运行时 API 指定要使用的布局。

# 为什么要使用布局

当项目中的很多页面都拥有相同的外层结构时，如果把这些结构重复写在每个页面里，会带来以下问题：

  • 公共区域代码重复，修改成本高
  • 页面结构不统一，维护时容易遗漏
  • 不同业务区块的页面边界不清晰
  • 后台、前台、登录页等场景难以拆分

布局系统正是用来解决这些问题的。它适合封装：

  • 网站通用头部和底部
  • 管理后台左侧菜单和顶部工具栏
  • 用户中心的二级导航容器
  • 全屏登录页、活动页、专题页等特殊页面结构

# 布局文件结构

Nuxt 会自动识别 layouts/ 目录中的 .vue 文件，并将其注册为可用布局。

# 布局与页面的关系

  • pages/ 负责具体页面内容
  • layouts/ 负责页面外层结构
  • 页面内容会插入到布局中的 <slot />
  • 若页面没有显式指定布局，默认会使用 layouts/default.vue

可以把布局理解成页面的“外壳”，页面组件本身只负责业务区域。

# 默认布局

layouts/default.vue 是默认布局文件。当页面没有声明 layout 时，Nuxt 会优先使用这个布局。

<!-- layouts/default.vue -->
<template>
  <div class="layout-default">
    <AppHeader />

    <main class="layout-main">
      <slot />
    </main>

    <AppFooter />
  </div>
</template>

<style scoped>
.layout-default {
  min-height: 100vh;
  display: flex;
  flex-direction: column;
}

.layout-main {
  flex: 1;
  padding: 24px;
}
</style>

# 布局命名规则

Nuxt 会根据布局文件名生成布局名称：

文件路径 布局名
layouts/default.vue default
layouts/admin.vue admin
layouts/user-center.vue user-center

页面中指定布局时，使用的是文件名，不带 .vue 后缀。

<script setup>
definePageMeta({
  layout: "admin",
});
</script>

# 布局书写规范

为了保证布局文件可维护，推荐遵循以下规范：

# 1. 只负责公共结构

布局应主要承担页面骨架职责，例如：

  • 顶部导航
  • 侧边栏
  • 面包屑容器
  • 页脚
  • 页面整体容器样式

不要把具体页面业务逻辑大量写进布局中，否则布局会变得臃肿。

# 2. 页面内容通过 <slot /> 输出

布局必须预留 <slot />，让页面内容有渲染位置。

<template>
  <div class="app-layout">
    <AppHeader />
    <slot />
  </div>
</template>

# 3. 公共区域尽量组件化

像 Header、Footer、Sidebar 这类内容，建议抽成独立组件后在布局中引入，而不是直接把大量模板写死在布局文件里。

<template>
  <div class="app-layout">
    <AppHeader />
    <AppSidebar />
    <main>
      <slot />
    </main>
  </div>
</template>

# 4. 布局命名要贴合业务语义

推荐使用能够表达用途的命名，例如：

  • default
  • admin
  • blank
  • user-center

避免使用含义不明确的名称，例如 layout1、test-layout。

# 5. 布局尽量保持轻量

布局适合承载通用外层结构，不建议在其中堆积过多数据请求和复杂副作用。如果确实需要公共数据，可以放入组合式函数或状态管理中统一处理。

# 切换布局

Nuxt 的布局切换既支持静态配置，也支持运行时动态切换。

这是最常见的方式，适合页面一开始就确定布局的场景。

<script setup>

# 方式二：通过 setPageLayout 动态切换

如果布局需要根据用户角色、页面状态、查询参数等条件决定，可以使用 setPageLayout。

<!-- pages/dashboard.vue -->
<script setup>
const user = useState("user", () => ({
  role: "admin",
}));

if (user.value.role === "admin") {
  setPageLayout("admin");
} else {
  setPageLayout("default");
}
</script>

<template>
  <div>
    <h1>仪表盘</h1>
    <p>根据用户角色动态切换布局。</p>
  </div>
</template>

# 方式三：在中间件中切换布局

如果布局切换逻辑和路由权限有关，可以在中间件中处理。

// middleware/admin-layout.ts
export default defineNuxtRouteMiddleware(() => {
  const token = useCookie("token");
  const role = useCookie("role");

  if (!token.value) {
    return navigateTo("/login");
  }

  if (role.value === "admin") {
    setPageLayout("admin");
  } else {
    setPageLayout("default");
  }
});

# 在 app.vue 中理解布局渲染

Nuxt 内部会使用 NuxtLayout 包裹当前页面，你也可以在 app.vue 中手动控制整体渲染结构。

<!-- app.vue -->
<template>
  <NuxtLoadingIndicator />
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
1
2
3
4

含义如下：

  • NuxtLayout 负责渲染当前页面匹配到的布局
  • NuxtPage 负责渲染当前路由页面
  • 页面最终会被插入布局中的 <slot />

渲染关系可以理解为：

NuxtLayout
└─ layouts/admin.vue 或 layouts/default.vue
   └─ &lt;slot />
      └─ NuxtPage
         └─ pages/xxx.vue

# 常见注意事项

# 1. 不要把页面内容写进布局

布局应该放“公共结构”，页面文件才放“具体业务内容”。如果布局里堆积了大量业务逻辑，会导致复用性下降。

# 2. 一定要保留 <slot />

如果忘记写 <slot />，页面虽然匹配到了布局，但页面主体内容不会显示。

# 3. 布局名称要与文件名一致

例如文件是 layouts/user-center.vue，那么页面中就应该写：

<script setup>
definePageMeta({
  layout: "user-center",
});
</script>

# 4. layout: false 和空白布局不是一回事

  • layout: false 表示完全不使用布局
  • layout: "blank" 表示仍然使用一个极简布局文件

如果你还需要统一背景、居中容器、登录页样式，通常更推荐使用 blank 这类空白布局。

# 总结

Nuxt.js 布局系统的核心点如下：

  • layouts/ 目录用于存放布局文件
  • default.vue 是默认布局，未声明布局时会优先使用
  • 页面通过 definePageMeta({ layout: "xxx" }) 指定命名布局
  • 可以通过 setPageLayout("xxx") 实现运行时动态切换
  • 布局文件本质上是页面公共外壳，页面内容通过 <slot /> 注入
  • 登录页、活动页等特殊页面可以使用 layout: false 或空白布局

在实际项目中，建议至少规划好 default、admin、blank 三类布局，这样前台页面、后台页面和特殊页面的结构会更加清晰。
