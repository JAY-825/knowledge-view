# Nuxt.js 组件

组件是 Nuxt.js 和 Vue 应用开发中最核心的组成单位之一。一个页面通常由多个组件组合而成，例如导航栏、轮播图、商品卡片、表单项、弹窗、页脚等。合理拆分组件，可以提高代码复用性、可维护性以及团队协作效率。

在 Nuxt 3 中，组件的使用方式比传统 Vue 项目更方便，因为它内置了组件自动导入能力。很多情况下，我们只需要把组件放进 components/ 目录中，就可以直接在页面或其他组件里使用，无需手动 import。

# 为什么要使用组件

如果把所有结构和逻辑都写在页面文件中，会带来很多问题：

  • 页面文件过大，不利于维护
  • 相同 UI 片段需要重复编写
  • 功能边界不清晰，复用困难
  • 团队协作时容易产生冲突

组件化开发可以把一个复杂页面拆分成多个职责明确的小模块，例如：

  • AppHeader 负责头部导航
  • ProductCard 负责商品卡片展示
  • UserAvatar 负责用户头像组件
  • BaseButton 负责通用按钮样式和行为

# 组件的基本书写

Nuxt 组件本质上仍然是 Vue 单文件组件，通常由以下几部分组成：

  • <template>：负责结构
  • <script setup>：负责逻辑
  • <style scoped>：负责样式

# 最简单的组件示例

<!-- components/AppHeader.vue -->
<template>
  <header class="app-header">
    <h1>{{ title }}</h1>
  </header>
</template>

<script setup>
const title = "Nuxt.js 学习站点";
</script>

<style scoped>
.app-header {
  padding: 20px;
  color: #fff;
  background: #00dc82;
}
</style>

# 组件书写规范

在实际项目中，组件不仅要能运行，还需要保持结构清晰、命名规范、职责明确。

# 1. 组件命名要有语义

推荐使用 PascalCase 命名：

  • AppHeader.vue
  • ProductCard.vue
  • UserAvatar.vue
  • BaseDialog.vue

不推荐：

  • header.vue
  • demo1.vue
  • aaa.vue

语义化命名可以让其他开发者一眼看出组件用途。

# 2. 一个组件只做一件事

例如商品卡片组件应聚焦于商品展示，不要同时承担商品列表请求、购物车逻辑、支付逻辑等过多职责。

# 3. 复用型组件与业务型组件分开

可以按用途区分：

  • 基础组件：BaseButton、BaseInput、BaseDialog
  • 业务组件：OrderTable、ProductCard、UserCenterSidebar

# 4. 尽量使用 props 和 emits 做数据通信

父组件向子组件传值使用 props，子组件通知父组件使用事件触发，这样结构最清晰。

# 5. 样式优先局部作用域

多数业务组件建议使用 <style scoped>，避免样式污染全局。

# 使用事件与父组件通信

  emit("click");

# 组件分组与自动导入建议

# 组件与页面的区别

在 Nuxt 中，pages/ 和 components/ 都是 .vue 文件，但职责不同。

目录 作用
pages/ 用于路由页面，会自动生成路由
components/ 用于可复用的 UI 与功能片段，不生成路由

例如：

  • pages/about.vue 访问路径可能是 /about
  • components/AboutCard.vue 只是一个普通组件，不能直接通过 URL 访问

# 使用客户端专属组件

有些组件依赖浏览器 API，例如：

  • window
  • document
  • 地图 SDK
  • 图表库

这类组件在服务端渲染时可能报错，可以使用 ClientOnly 包裹。

<!-- pages/chart.vue -->
<template>
  <div>
    <h1>图表页面</h1>

    <ClientOnly>
      <ChartPanel />
    </ClientOnly>
  </div>
</template>

# 组合式函数与组件配合

当多个组件需要复用同一套逻辑时，不要把逻辑复制到每个组件中，更推荐抽到 composables/ 目录。

// composables/useCounter.ts
export function useCounter() {
  const count = useState("count", () => 0);

  function increment() {
    count.value += 1;
  }

  return {
    count,
    increment,
  };
}

# 常见注意事项

# 1. 自动导入不代表可以随意命名

组件命名依旧需要保持清晰，否则页面里出现大量不明确标签会降低可读性。

# 2. 组件过大时要及时拆分

如果一个组件同时包含列表、弹窗、筛选栏、分页、请求逻辑，通常说明它已经太大，应该继续拆分。

# 3. 复用优先，不要过度抽象

不是所有重复两次的结构都必须抽成组件。只有在明确会复用、结构稳定、职责清晰时，抽离组件才更有价值。

# 4. 优先使用自动导入，特殊场景再手动导入

对于 Nuxt 项目来说，自动导入可以减少模板代码；但在依赖来源需要明确表达时，也可以保留手动导入写法。

# 5. 组件负责展示，复杂逻辑可以下沉

共享逻辑适合放入：

  • composables/
  • stores/
  • utils/

这样组件本身会更轻、更容易维护。

# 总结

Nuxt.js 组件系统的核心点如下：

  • 组件是页面 UI 和功能拆分的基本单元
  • 组件通常放在 components/ 目录中
  • 页面和组件都可以直接使用自动导入的组件
  • 父子通信主要依赖 props、事件和 slot
  • Nuxt 支持手动导入，也支持默认自动导入
  • 自动导入时会根据目录结构生成组件名称
  • 可以通过 nuxt.config.ts 自定义组件扫描规则
  • 对于浏览器专属内容可以结合 ClientOnly
  • 对于体积较大的组件可以使用 Lazy 前缀实现懒加载

在实际项目中，建议建立一套清晰的组件命名和分层规范，这样随着项目规模增大，组件系统依然能够保持整洁、有序、易扩展。
