# MutationObserver（DOM 变更观察器）

MutationObserver 是浏览器提供的 Web API，用于监听 DOM 结构与节点属性、文本内容的变化。它会把一段时间内发生的变更批量收集起来，在一次异步回调中统一通知，从而替代早期性能较差且已弃用的 DOM Mutation Events（如 DOMNodeInserted）。

# 一、能解决什么问题

# 1. 常见应用场景

  1. 监听列表/容器中节点新增与移除（例如渲染后自动给新增节点绑定行为）
  2. 监听属性变化（例如 class、style、data-* 变化后触发联动）
  3. 监听文本变化（例如 contenteditable 输入、富文本渲染变化）
  4. 组件化/插件化增强（第三方组件渲染完毕后再执行二次增强）
  5. 调试与分析（定位谁在频繁改 DOM，或监控某个区域是否被改写）

# 2. 与轮询、事件监听的区别

  • 与定时器轮询相比：MutationObserver 是事件驱动、批量回调，通常更省资源
  • 与事件监听相比：很多 DOM 变化没有对应的事件（例如第三方脚本直接改 DOM），此时观察器更可靠

# 二、基础用法

MutationObserver 的使用步骤通常分为三步：

  1. new MutationObserver(callback)
  2. observer.observe(target, options)
  3. 需要时 observer.disconnect()

# 1. 最小示例：监听子节点变化

<div id="list"></div>
<button id="add">Add</button>
<script>
  const list = document.querySelector('#list');

  const observer = new MutationObserver((mutationList) => {
    for (const mutation of mutationList) {
      if (mutation.type === 'childList') {
        console.log('added:', mutation.addedNodes);
        console.log('removed:', mutation.removedNodes);
      }
    }
  });

  observer.observe(list, { childList: true });

  document.querySelector('#add').addEventListener('click', () => {
    const item = document.createElement('div');
    item.textContent = `item-${Date.now()}`;
    list.appendChild(item);
  });
</script>

# 三、API 速查

# 1. MutationObserver 构造函数

const observer = new MutationObserver((mutationList, obs) => {});
1
  • callback 第一个参数是 MutationRecord 数组，按发生顺序批量提供
  • callback 第二个参数是当前 observer 实例

# 2. observe(target, options)

observer.observe(targetNode, options);
1

target 必须是 Node（常见为 Element 或 Document）。

# 3. disconnect()

observer.disconnect();
1

停止观察，释放引用，避免泄漏与多余开销。

# 4. takeRecords()

const pending = observer.takeRecords();
1

取出尚未交给回调处理的变更记录（如果你想主动“清空/拉取”队列）。

# 四、options（观察配置）详解

options 是 MutationObserver 的关键，它决定“观察哪些变化”与“记录哪些细节”。

# 1. childList：子节点新增/移除

observer.observe(target, { childList: true });
1
  • 记录 addedNodes、removedNodes

# 2. subtree：观察整个子树

observer.observe(target, { childList: true, subtree: true });
1
  • 当你希望监控某个容器内任何层级的变更时使用
  • subtree 会明显扩大观察范围，尽量配合过滤条件减少处理量

# 3. attributes：属性变化

observer.observe(target, { attributes: true });
1

相关增强选项：

  • attributeOldValue：记录变化前的属性值
  • attributeFilter：只监听指定属性名数组（强烈建议用于降噪）
observer.observe(target, {
  attributes: true,
  attributeOldValue: true,
  attributeFilter: ['class', 'style', 'aria-hidden']
});

# 4. characterData：文本节点变化

observer.observe(target, { characterData: true, subtree: true });
1

相关增强选项：

  • characterDataOldValue：记录变化前文本内容

# 五、MutationRecord（变更记录）字段说明

每条变更记录是一个 MutationRecord，常见字段如下：

  • type：'attributes' | 'characterData' | 'childList'
  • target：发生变更的节点
  • addedNodes / removedNodes：childList 时有效（NodeList）
  • previousSibling / nextSibling：childList 时有效
  • attributeName / attributeNamespace：attributes 时有效
  • oldValue：当你开启 attributeOldValue 或 characterDataOldValue 时有效

# 六、实用案例

# 1. 只关心新增节点：自动增强新插入的元素

需求：某个区域动态插入按钮，插入后自动补充行为（例如给 data-action 的元素绑定点击）。

const root = document.querySelector('#root');

function enhance(node) {
  if (!(node instanceof Element)) return;
  const clickable = node.matches('[data-action]')
    ? [node]
    : Array.from(node.querySelectorAll('[data-action]'));

  for (const el of clickable) {
    if (el.dataset.bound === '1') continue;
    el.dataset.bound = '1';
    el.addEventListener('click', () => {
      console.log('action:', el.dataset.action);
    });
  }
}

const observer = new MutationObserver((records) => {
  for (const r of records) {
    if (r.type !== 'childList') continue;
    r.addedNodes.forEach(enhance);
  }
});

observer.observe(root, { childList: true, subtree: true });

# 2. 监听 class 变化：状态联动

const panel = document.querySelector('#panel');

const observer = new MutationObserver((records) => {
  for (const r of records) {
    if (r.type !== 'attributes') continue;
    if (r.attributeName !== 'class') continue;
    const isOpen = panel.classList.contains('open');
    console.log('panel open:', isOpen, 'old:', r.oldValue);
  }
});

observer.observe(panel, {
  attributes: true,
  attributeOldValue: true,
  attributeFilter: ['class']
});

# 3. 防止“自触发循环”：在回调内修改 DOM 的正确姿势

MutationObserver 回调里如果再次修改被观察区域的 DOM，可能会再次触发观察器，造成循环或性能放大。

处理方式之一：在回调内临时断开，修改完成后再恢复观察。

const target = document.querySelector('#target');

const observer = new MutationObserver((records) => {
  observer.disconnect();
  try {
    for (const r of records) {
      if (r.type === 'childList' && r.addedNodes.length > 0) {
        target.querySelectorAll('img:not([loading])').forEach((img) => {
          img.loading = 'lazy';
        });
      }
    }
  } finally {
    observer.observe(target, { childList: true, subtree: true });
  }
});

observer.observe(target, { childList: true, subtree: true });

# 4. 批处理与节流：把频繁变更合并到一帧中处理

MutationObserver 回调会批量交付记录，但如果 DOM 变化非常频繁，你仍然可能在短时间内收到很多次回调。可以把实际处理合并到 requestAnimationFrame 中。

const root = document.querySelector('#root');
let scheduled = false;
let pending = [];

const observer = new MutationObserver((records) => {
  pending.push(...records);
  if (scheduled) return;
  scheduled = true;
  requestAnimationFrame(() => {
    scheduled = false;
    const recordsToHandle = pending;
    pending = [];
    const added = [];
    for (const r of recordsToHandle) {
      if (r.type === 'childList') added.push(...r.addedNodes);
    }
    console.log('added nodes count:', added.length);
  });
});

observer.observe(root, { childList: true, subtree: true });

# 七、最佳实践与注意事项

  1. 尽量缩小观察范围：优先监听具体容器，而不是 document.body
  2. 充分利用 attributeFilter：监听 attributes 时强烈建议指定过滤属性，减少噪音
  3. 及时 disconnect：页面卸载、组件销毁、观察完成后应断开
  4. 避免回调里大量同步计算：必要时用 requestAnimationFrame / setTimeout 做合并
  5. 小心引用导致的泄漏：观察器持有 target 引用，组件销毁时不 disconnect 容易泄漏
  6. 理解“异步批量回调”：回调不是在每次 DOM 操作的同一行同步触发，而是把一段时间的变更聚合后再触发

# 八、常见问题

# 1. 为什么我修改 DOM 后回调没有立刻触发

MutationObserver 的通知是异步的，浏览器会把变更记录入队，然后在合适的时机批量触发回调。不要依赖它的“立即性”，更适合做“变更后处理”。

# 2. 如何只监听某个容器内新增的特定元素

做法：childList + subtree，然后在 addedNodes 里筛选 Element，并用 matches/querySelectorAll 找目标节点。

# 3. 它能监听样式变化吗

能监听通过 DOM 属性写入的变化（例如 style 属性字符串变更，或 class 变更）；但 CSS 计算后的样式变化（例如媒体查询导致的计算样式变化）不是 DOM 变更，MutationObserver 不负责。
