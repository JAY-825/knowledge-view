# JavaScript 内存管理与垃圾回收

本文系统介绍 JavaScript 的内存生命周期、自动内存管理与常见垃圾回收（GC）策略，并给出可操作的内存友好实践与代码示例，帮助你写出更稳定高效的前端/Node.js 程序。

# 内存生命周期

  • 分配：为新值/对象分配内存
  • 使用：读写已分配内存（变量访问、属性读写、函数参数传递等）
  • 释放：当值“不再需要”时，释放其占用的内存

在 JavaScript 中，分配与释放通常由引擎自动完成（垃圾回收）。

const o = { x: 1, y: 2 }; // 对象、数组、函数、闭包等分配于堆

# 内存管理与“可达性”

  • 可达性：从一组根（如全局对象、当前作用域的局部变量、闭包可见变量、活动的回调、原生宿主引用等）出发，通过引用可触达的对象即为“可达”；不可达即“可回收”
  • 释放的本质：让对象变为不可达（离开作用域、移除引用、解除关联）
let obj = { big: new Array(10_000).fill(0) };
obj = null; // 解除最后一个引用，使其不可达，等待 GC 回收

# 垃圾回收（GC）策略

  • 标记-清除（Mark-and-Sweep）

    • 从根开始标记可达对象，未标记的即不可达，随后清除不可达对象
    • 能正确处理循环引用（对比早期的引用计数）

  • 代际 GC（Generational GC）

    • 将堆分为新生代与老生代：新对象通常“朝生暮死”，频繁在新生代收集；长期存活对象晋升到老生代，降低扫描成本

  • 增量/并发/并行 GC

    • 将一次性停顿（STW）拆分为增量步骤；并发/并行地在后台执行标记与清理，减少对应用的影响

以上策略是现代引擎（V8、SpiderMonkey、JavaScriptCore）在标记-清除基础上的工程改进。

# 内存友好实践

  • 避免隐式全局：启用严格模式或使用构建检查；所有变量用 let/const 声明
  • 生命周期管理
    • 定时器：在组件卸载/任务结束时清理 setInterval/setTimeout
    • 事件：配合 addEventListener 的 signal/{ once: true }，或手动 removeEventListener
    • 异步资源：取消请求（AbortController）、关闭 WebSocket、释放对象句柄
  • 使用弱引用容器
    • WeakMap/WeakSet：键是对象的弱引用，不阻止 GC；适合为对象附加元数据、缓存解析结果
const meta = new WeakMap();
function attach(o) { meta.set(o, compute(o)); }
// o 被外部丢弃后，meta 中的条目也会被 GC

  • 适度缓存与驱逐策略

    • LRU/LFU/TTL 缓存；限制最大项数与总内存占用

  • 及时释放大对象

    • 用完即置 null 或让其脱离作用域；分块处理大型数据（流式/分段）

  • 数据结构选择

    • 避免把巨量数据驻留在前端；对二进制使用 ArrayBuffer 的 transfer 或可调整大小避免复制

  • 文本与二进制

    • 使用 TextDecoder/TextEncoder、Blob/File、ArrayBuffer 与 DataView 进行高效处理

  • 工具与监控

    • 浏览器 Performance/Memory 面板、Heap Snapshot、Allocation Timeline；Node.js 使用 --max-old-space-size 等 V8 选项与 clinic/heapdump

# 垃圾回收与不可达的思路训练

  • 判断对象是否仍需：是否在未来代码路径中会被访问？是否仅因“缓存/便利”而存在？
  • 引入“归还/释放”语义：完成后显式解绑定（监听/句柄/大量内存块）
  • 关注“根”的来源：全局单例、闭包持有、宿主持有（DOM、定时器、任务队列）

# Node.js 内存与配置提示

  • 生产服务可按需调整老生代最大空间：node --max-old-space-size=2048 app.js
  • 采集堆快照与内存泄漏分析：heapdump、clinic flame 等工具

# 浏览器 DevTools 内存分析实操

  • 目标：复现内存增长、识别不可达前的持有链、定位泄漏来源并验证修复
  • 面板入口：Chrome DevTools → Memory（或 Performance 面板结合 JS Heap 指标）

# 三种采集方式与适用场景

  • Heap snapshot：采集堆快照，适合精确查看对象图、对比前后快照、分析保留大小（Retained Size）与持有者链（Retainers）
  • Allocation instrumentation on timeline：录制时间轴上的对象分配；适合定位何时、在哪段交互出现分配峰值与未被回收对象
  • Allocation sampling：采样分配栈；性能开销更低，适合长期观察热点分配路径

# Heap snapshot 操作清单

  • 刷新页面，执行一次“拍摄快照”（Snapshot A）
  • 复现疑似泄漏操作（多次导航、打开/关闭弹窗、数据轮询等），再次拍摄快照（Snapshot B、C）
  • 使用“Comparison”（比较）模式：
    • 按 Constructor 排序，查看 Retained Size 增长显著的类型
    • 展开条目，进入 Retainers 面板，检查对象为何仍被持有（闭包、事件监听、定时器、Detached DOM）
    • 重点关注：Detached HTMLDivElement、(array)、Closure、Window、Document 等持有链
  • 过滤：使用筛选输入 detached，快速定位被分离的 DOM 树
  • 验证修复：移除监听/清理定时器/断开引用后，重复快照对比，应见 Retained Size 回落

# 时间轴分配分析

  • 选择 Allocation instrumentation on timeline
  • 点击 Start，按真实使用路径进行交互，点击 Stop
  • 在瀑布图中选中有峰值的时间段，右侧对象列表按 Constructor/Retained Size 排序
  • 逐项查看分配来源与调用栈（可与 Sources 面板联动定位代码位置）
  • 结合“Display garbage”/“Filter by allocation stack”选项，观察是否发生回收

# 常见线索与定位技巧

  • Detached DOM：说明节点脱离文档但仍被 JS 引用（事件监听/闭包/缓存）
  • Closure：闭包持有大数组/对象导致无法回收
  • Timer/Interval：漏掉 clearTimeout/clearInterval
  • Global/Singleton：单例长持有导致驻留；将大对象移出全局，按需加载与释放

# 总结

  • 让对象在使用完后尽快“不可达”，剩下交给 GC
  • 识别并避免长生命周期持有：定时器、事件、缓存、闭包、大型结构
  • 使用弱引用与流式处理等技术，降低驻留占用
  • 利用监控工具定位泄漏与突增，迭代优化

# LRU 缓存实现示例（含 TTL）

class LRUCache {
  constructor(limit = 100) {
    this.limit = limit;
    this.map = new Map();
  }
  get(key) {
    if (!this.map.has(key)) return undefined;
    const value = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, value);
    return value;
  }
  set(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.limit) {
      const oldest = this.map.keys().next().value;
      this.map.delete(oldest);
    }
  }
  has(key) { return this.map.has(key); }
  size() { return this.map.size; }
  clear() { this.map.clear(); }
}

class TTLLRUCache extends LRUCache {
  constructor(limit = 100, ttl = 60_000) {
    super(limit);
    this.ttl = ttl;
  }
  get(key) {
    const entry = super.get(key);
    if (!entry) return undefined;
    const { value, expiresAt } = entry;
    if (Date.now() > expiresAt) {
      this.map.delete(key);
      return undefined;
    }
    return value;
  }
  set(key, value) {
    super.set(key, { value, expiresAt: Date.now() + this.ttl });
  }
}

// 使用示例
const cache = new TTLLRUCache(1000, 5 * 60_000);
function getUser(id) {
  const hit = cache.get(id);
  if (hit !== undefined) return hit;
  const fresh = /* fetch or compute */ id;
  cache.set(id, fresh);
  return fresh;
}

# LRU 测试用例（浏览器/Node 通用）

// 依赖上文的 TTLLRUCache/LRUCache 定义
const cache = new TTLLRUCache(3, 1000);

cache.set('a', 1);
cache.set('b', 2);
cache.set('c', 3);
cache.get('a');         // 访问 a，使其成为最近使用
cache.set('d', 4);      // 触发淘汰：应当淘汰 'b'

const keys = () => Array.from(cache.map.keys());
console.log(keys());    // ['c','a','d'] 或 ['a','c','d']，取决于实现顺序

setTimeout(() => {
  console.log(cache.get('a')); // 过 TTL 后为 undefined（已过期）
}, 1100);

// Node 下观察堆占用（可选）
if (typeof process !== 'undefined' && process.memoryUsage) {
  const before = process.memoryUsage().heapUsed;
  for (let i = 0; i < 10000; i++) cache.set('k' + i, i);
  const after = process.memoryUsage().heapUsed;
  console.log('heap delta(bytes):', after - before);
}
