# JavaScript 原型与原型链

面向对象的 JavaScript 以“原型”为基础构建对象关系与行为复用。理解 prototype、__proto__/[[Prototype]]、constructor 以及属性查找规则，是读懂框架源码与编写高质量代码的关键。

# 显式原型与隐式原型

  • 显式原型（prototype）：存在于“函数对象”上，指向“实例的原型对象”。仅可构造的函数才有可用的 prototype。
  • 隐式原型（__proto__/[[Prototype]]）：存在于“任意对象”上，指向其“原型对象”。属性读取会沿着该引用组成的链路逐级查找。
function Fn() {}
// 显式原型：函数上的 prototype
Fn.prototype.greet = function () { return 'hi'; };

// 通过 new 生成实例时，实例的隐式原型指向 Fn.prototype
const obj = new Fn();
// 等价关系：obj.__proto__ === Fn.prototype
Object.getPrototypeOf(obj) === Fn.prototype; // true

它们的关系：obj.__proto__（隐式原型）指向某个原型对象；当这个原型对象来自构造函数的 Fn.prototype（显式原型）时，就形成了“实例 ↔ 构造函数”之间的原型纽带。

原型链拼合：obj -> obj.__proto__(= Fn.prototype) -> Fn.prototype.__proto__(= Object.prototype) -> null

# 核心概念速览

  • prototype：函数对象的一个属性，指向“实例的原型对象”。只有“可构造的函数”才有可用的 prototype。
  • [[Prototype]]：每个对象内部的隐藏引用，指向其原型对象。多数运行时通过非标准访问器 __proto__ 暴露出来。
  • constructor：默认挂在原型对象上，指回构造函数本身（可被重置，需要手动修复）。
  • 原型链：对象在读取属性时，沿着 [[Prototype]] 逐级向上查找的链式结构，直到 null 停止。

# 属性查找规则（读取时）

  1. 先查对象自身的“自有属性”（own properties）。
  2. 未命中则沿 [[Prototype]] 向上查找原型对象的属性。
  3. 若到达顶层（Object.prototype 的再上一层是 null）仍未命中，则返回 undefined。

写入不同：给对象新增属性会直接写在对象自身；若写入同名的访问器属性或被只读限制，行为会不同（需结合 Object.defineProperty 的描述符理解）。

# 创建对象与原型的常见方式

// 1) 字面量对象 —— 原型是 Object.prototype
const o1 = { a: 1 };
Object.getPrototypeOf(o1) === Object.prototype; // true

// 2) 构造函数 + new
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  return `Hi, I am ${this.name}`;
};
const p = new Person('Jay');
p.sayHi(); // 'Hi, I am Jay'
Object.getPrototypeOf(p) === Person.prototype; // true

// 3) Object.create —— 直接指定 [[Prototype]]
const base = { kind: 'base' };
const o2 = Object.create(base); // o2.__proto__ === base
o2.kind; // 'base'

# new 的执行过程（四步）

  1. 创建一个全新的空对象 obj。
  2. 关联原型：obj.[[Prototype]] = Fn.prototype。
  3. 执行构造函数：以 obj 作为 this 调用 Fn，注入属性。
  4. 返回：若构造函数返回对象，则返回该对象；否则返回 obj。

# 原型链示例与图示

function A() {}
A.prototype.x = 1;

function B() {}
B.prototype.y = 2;

// 让 A 的原型指向 B 的实例，实现“原型链上的继承”
Object.setPrototypeOf(A.prototype, B.prototype);

const a = new A();
a.x; // 1（来自 A.prototype）
a.y; // 2（沿原型链到 B.prototype）

# 继承/复用的常见模式

  • 原型继承：通过 Object.create(parentProto) 或调整 Child.prototype.__proto__。
  • 组合继承：构造函数内 Parent.call(this, ...) + Child.prototype = Object.create(Parent.prototype)，同时修复 constructor。
  • 寄生组合继承：避免多余的父构造函数调用，仅一次原型初始化（推荐经典方案）。
  • ES6 class/extends：语法糖，底层仍基于原型链；super 处理父类构造与方法。
function Parent(name) { this.name = name; }
Parent.prototype.say = function () { return this.name; };

function Child(name, age) {
  Parent.call(this, name); // 组合继承：复制父类实例属性
  this.age = age;
}
Child.prototype = Object.create(Parent.prototype); // 链接原型方法
Child.prototype.constructor = Child; // 修复 constructor 指向

# 归属与枚举：in vs hasOwnProperty

  • prop in obj：沿原型链查找，只要能读到就返回 true。
  • obj.hasOwnProperty(prop)：仅判断“自有属性”。
  • Object.keys(obj)：仅枚举可枚举的自有属性（不含原型属性）。
  • for...in：枚举自有 + 原型上的可枚举属性（不推荐用于数组/大型对象）。

# 修改原型的注意点

  • 重置整个 Fn.prototype = { ... } 会丢失默认的 constructor，需手动恢复：
function Fn() {}
Fn.prototype = {
  greet() { return 'hi'; }
};
Object.defineProperty(Fn.prototype, 'constructor', {
  value: Fn,
  enumerable: false
});

  • Object.setPrototypeOf(obj, proto) 性能较差且影响优化；更推荐 Object.create(proto) 在创建时指定。

# 内置对象的原型链速记

  • 普通对象：obj -> Object.prototype -> null
  • 数组：arr -> Array.prototype -> Object.prototype -> null
  • 函数：fn -> Function.prototype -> Object.prototype -> null
  • 原型顶端：Object.prototype.__proto__ === null
  • 特性：箭头函数不可构造（无 prototype），class 声明本质上创建构造函数并设置原型链。

# 常用原型相关 API

  • Object.getPrototypeOf(obj)：读取 [[Prototype]]。
  • Object.setPrototypeOf(obj, proto)：设置原型（不推荐频繁使用）。
  • Object.create(proto, descriptors?)：以 proto 为原型创建新对象。
  • Object.prototype.isPrototypeOf(obj)：判断自身是否出现在对象的原型链上。
  • Reflect.get(obj, prop, receiver?)：更细粒度的属性读取控制（可影响 getter 中的 this）。

# 典型易错点与实践建议

  • 误把 prototype 当作实例的属性：prototype 属于“函数对象”，实例访问的是其 [[Prototype]]。
  • 重置原型后忘记修复 constructor，影响类型判断与序列化。
  • 滥用 for...in 导致意外枚举到原型属性。
  • 在热更场景频繁调用 Object.setPrototypeOf 影响性能与 JIT 优化。
  • 继承层级过深导致调试困难；优先组合/委托而非层层继承。

# FAQ

  • class 和原型链的关系？
    • class 是语法糖：为函数构造器与其 prototype 提供更直观的声明方式，同时自动设置继承链与 super 调用。
  • 为什么有 __proto__ 和 Object.getPrototypeOf 两套？
    • __proto__ 是早期约定，后被标准以遗留形式收录；推荐用标准 API 进行读写。

# 总结

原型定义了对象的“共享行为”，原型链提供了“逐级查找”的机制。掌握对象创建、属性查找、继承模式与常用 API，能写出更可读、可维护且性能友好的 JavaScript 代码。
