# 类型

TypeScript 的类型系统在 JavaScript 的运行时语义之上提供静态约束。掌握基础与高级类型能显著提升代码的健壮性与表达力。

# 基础类型

  • string、number、boolean、bigint、symbol
  • null、undefined（在 strictNullChecks 下需显式包含）
  • void 表示函数无返回值
  • object 表示非原始类型
let s: string = 'hi';
let n: number = 42;
let b: boolean = true;
function log(x: string): void {}

# 字面量与联合类型

  • 字面量类型：'on' | 'off'、1 | 2 | 3
  • 联合类型：A | B 表示可能是 A 或 B
  • 交叉类型：A & B 合并多个类型的属性
type Toggle = 'on' | 'off';
interface A { a: number }
interface B { b: string }
const v: A & B = { a: 1, b: 'x' };

# 数组与元组

  • 数组：string[] 或 Array<string>
  • 元组：定长且定类型的数组，如 [number, string]
const arr: number[] = [1, 2];
const pair: [number, string] = [10, 'id'];

# any、unknown、never

  • any 跳过类型检查，慎用
  • unknown 需要收窄后才能使用
  • never 不会发生的返回类型（抛错或死循环）
function fail(msg: string): never { throw new Error(msg) }
function parse(x: unknown) {
  if (typeof x === 'string') return x.toUpperCase();
}

# 类型别名与接口

  • 类型别名：type Name = ...
  • 接口：interface Name { ... }
  • 二者都能描述对象结构；接口支持声明合并，类型别名支持联合/交叉/条件等高级组合
type Id = string | number;
interface User { id: Id; name: string }

# 类型收窄与保护

  • typeof、instanceof、自定义类型谓词实现收窄
function isDate(x: unknown): x is Date { return x instanceof Date }
function format(x: unknown) { if (isDate(x)) return x.toISOString() }

# 索引签名与键查询

  • keyof T 获取类型 T 的所有键的联合类型
  • 索引访问：T[K] 获取属性类型
  • 映射类型：对键进行批量变换
interface Config { host: string; port: number }
type Keys = keyof Config; // 'host' | 'port'
type HostType = Config['host'];

type Readonly<T> = { readonly [K in keyof T]: T[K] };

# 条件类型与工具类型

  • 条件类型：T extends U ? X : Y
  • 分布式条件类型：对联合类型逐项分发
type Nullable<T> = T | null | undefined;
type NonNullable<T> = T extends null | undefined ? never : T;

常用工具类型（内置）：Partial、Required、Readonly、Pick、Record、Omit、ReturnType、Parameters、InstanceType 等。

# 模块与命名空间类型

  • 使用 ES 模块；通过 import type 进行仅类型导入，避免运行时开销
  • declare global 可扩展全局类型；谨慎使用以避免污染

# type 与 interface 的相同点

  • 都能描述对象结构、函数签名、索引签名
  • 都能被类实现（implements）
  • 都能通过泛型参数增强复用性
  • 在类型注解、函数参数、返回值等位置可互换使用

# type 与 interface 的不同点

维度 type 别名 interface
声明合并 不支持；同名会冲突 支持；同名接口自动合并
扩展方式 借助交叉类型 & 使用 extends 关键字
能力范围 可表达联合、交叉、条件、映射、模板字面量等任意类型组合 仅描述对象、函数、类契约
递归 需配合接口或类才能直接递归 可直接递归引用自身
工具类型 可定义 Partial<T> 这类工具类型 不能定义，只能借助 type 实现
映射类型 支持 { [K in keyof T]: ... } 不支持
可读性 复杂组合类型可读性稍差 对象结构清晰、语义化强

# 使用场景与区分原则

# 优先使用 interface 的场景

  1. 定义公共对象契约（组件 Props、API 响应）
  2. 需要利用声明合并扩展第三方库类型
  3. 类实现契约（class Foo implements Bar）
  4. 语义化表达“对象长什么样”

# 优先使用 type 别名的场景

  1. 表达联合类型：type Status = 'loading' | 'success' | 'error'
  2. 表达交叉类型：type A = B & C
  3. 定义工具类型或复杂映射：type DeepPartial<T> = ...
  4. 需要给任意类型（原始、联合、条件结果）起别名
  5. 临时类型，无需被他人扩展或实现

# 混合策略

  • 先用 interface 描述“对象骨架”，再用 type 做组合、联合、映射
  • 对外暴露的公共 API 用 interface，内部实现细节用 type
  • 若类型需要被消费者扩展（如插件系统），用 interface；若希望封闭、不可扩展，用 type
