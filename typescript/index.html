# TypeScript介绍

TypeScript 是在 JavaScript 之上增加静态类型系统与部分语言特性的编程语言。其核心目标是通过类型检查在开发期捕获错误、提升可维护性与可重构能力，同时输出兼容的 JavaScript。

# 关键特性

  • 静态类型：通过类型注解与类型推断发现潜在错误
  • 结构化类型系统：基于“形状匹配”的鸭子类型（structural typing）
  • 现代语法：支持最新 ECMAScript 提案并降级编译到目标环境
  • 工程能力：tsconfig.json 配置编译目标、路径别名、严格模式等
  • 丰富的类型工具：联合、交叉、条件、映射、索引访问、keyof 等

# 编译与配置

  • 入口文件：通常是 src/index.ts
  • 编译器：tsc 负责将 TS 编译为 JS
  • 配置文件：tsconfig.json 控制编译选项与包含/排除文件
  • 重要选项：
    • target 输出的 JS 版本，如 ES2019
    • module 模块系统，如 ESNext、CommonJS
    • strict 开启所有严格类型检查
    • baseUrl 与 paths 配置路径别名

# 类型系统要点

  • 类型注解与推断：能省则省，推断优先，必要处显式标注
  • any 与 unknown：尽量避免 any，优先 unknown 并进行类型收窄
  • never：表示不可能返回或不可到达的分支
  • 结构兼容性：属性子集可赋值给属性超集的类型
  • 宽化（widening）与收窄（narrowing）：字面量到更宽类型的推断与通过控制流进行收窄

# 类型声明与第三方库

  • 类型声明文件：*.d.ts 提供仅类型的声明，不包含运行时实现
  • DefinitelyTyped：社区维护的类型库，通过 npm i -D @types/<pkg> 安装
  • 与 JS 代码混用：允许在 JS 中通过 JSDoc 注释获得类型检查

# 工具与生态

  • 构建：tsc、esbuild、swc、vite、webpack
  • 运行：ts-node、tsx
  • 测试：Jest、Vitest 等测试框架的 TS 集成

# 实用规范

  • 开启 strict，最小化 any 的使用
  • 公共 API 使用精确的类型与文档，内部实现可借助 private/protected
  • 与运行时保持一致的约束，如不可空、边界条件、错误类型
  • 利用泛型与工具类型复用类型逻辑，避免重复定义
